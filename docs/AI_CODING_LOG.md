# AI Coding 使用记录

> 项目：SalesDeck 销售作战室
> 时间：2026-11-03 → 2026-11-09
> 工具：Claude Code（终端内 AI Coding Agent，会话模型标识 `deepseek-flash[1m]`）
> 仓库：本地 Git（`feature/salespilot` 分支），最终提交到 GitHub

这份记录说明 AI 在本项目中**做了什么、怎么被约束、产出如何被验证**，不是「AI 一键生成」的展示稿。

## 1. 协作方式

整体采用「先设计、再计划、后实现、每步验证」的流程：

1. **需求澄清**：用 brainstorming 流程把「销售问 AI」拆成「AI 销售作战室」，先产出设计文档 `docs/superpowers/specs/2026-11-07-salesdeck-war-room-design.md`。
2. **编写实施计划**：拆成 23 个任务，落到 `docs/superpowers/plans/2026-11-07-salesdeck-war-room.md`，每个任务带文件路径、测试与验收命令。
3. **实现**：优先 TDD（先写失败测试，再实现，再跑全量测试）；大规模并行任务曾尝试子代理逐任务实现，后因反馈「太慢」切换为主会话内联实现。
4. **人工验收**：用户逐页点击，提出体验/业务问题；AI 复现、定位、补测试、再提交。
5. **持续回归**：每个阶段跑 `typecheck`、单元测试、Playwright、Agent 评测。

## 2. 人工给出的关键指令（摘录）

以下是实际对话中决定项目走向的指令，不是事后编写的示例：

- **方向**：
  > 不是重新开发一个 CRM，而是在现有 SalesPilot 代码基础上进行产品级重构……从「销售主动问 AI」升级为「AI 销售作战室」。
- **安全边界**：
  > AI 不能绕过权限。AI 不能直接突破价格底线。AI 不能绕过审批。AI 写操作必须继续：预览 → 确认 → 执行。
- **流程调整**：
  > 太慢了，是不是子代理的问题。
- **体验纠错**：
  > 按钮不是在下面嘛怎么说上面，其次那些括号里的是啥？还有按钮的问题，上一个问题的按钮或者说是报价为什么下一个问题还夹在中间，还有发送对话之后位置不变，得手动下滑才看得到新对话。
- **业务状态纠错**：
  > 这个经理审批我已经驳回了还在这，销售工作台也没有驳回的反应。
  > 我驳回了还显示已批准。
  > 所以销售被驳回之后呢？有什么操作编辑空间嘛？
- **业务逻辑复查**：
  > 你再检查一下项目的业务逻辑。我就发现了经理和销售都编辑不了信用额度。这些种种不可编辑但得编辑的东西。
- **最终交付**：
  > 项目名不要叫 salespilot，换一个；API 不能只有 DeepSeek；还要 Cloudflare 做内网穿透；完善 README、接口契约说明、AI Coding 使用记录，再提交到 GitHub。

## 3. 分阶段记录

### 2026-11-03：基础能力

- 产出 Dockerfile、评测框架、演示文档。

### 2026-11-04：对话连续性

- 修复多轮会话上下文丢失，补充「先追问再执行」的分支。
- 增加跨轮 E2E：同一 `conversationId` 必须延续。

### 2026-11-07：从工作台到作战室

- 新增 `opportunities`、`follow_ups`，报价/订单显式关联商机。
- 实现优先级引擎：金额 × 概率 × 紧迫度 × 风险，输出 P0/P1/P2 与原因。
- 实现 workspace 聚合、经理驾驶舱、客户推进中心。
- 新增主动型工具：`get_sales_priorities`、`get_opportunity_detail`、`log_follow_up`、`update_opportunity_next_action`、`suggest_actions`。
- 首页重构为销售作战室。

### 2026-11-08：体验与审批生命周期

用户逐项验收后，AI 修复：

- AI 回复泄漏内部参数（`scope=self`、`dryRun`）→ 增加 `sanitizeAssistantText` 与提示词规则。
- AI 说「上面的选项」但按钮在下面 → 新增 `suggest_actions` 工具 + 可点击 artifact。
- 上一轮的报价卡残留到下一轮 → 发送时 `clearTransient()`。
- 新消息不可见 → 自动滚动。
- 审批被驳回后卡片仍显示 → 审批页清理、审批卡查询最新状态。
- 驳回后销售无操作路径 → 「记录跟进 + 修订报价 + 申请提额」。
- 信用提额闭环：销售申请、经理审批、额度更新后可直接转单。
- 拆单转订单：`converted_quantity`、部分金额/税、部分库存/信用、全部转完才关单。

### 2026-11-09：可编辑性补全与交付

用户反馈「经理和销售都编辑不了信用额度」，AI 做了一次完整的业务逻辑复查，补齐：

- 经理直接调额（不得低于已用、作废待审批申请）；销售客户页申请提额。
- 新建客户；编辑客户基础资料；经理改等级/负责人/状态。
- 联系人增删改与主要联系人顺延。
- 商机完整编辑（名称/金额/阶段/概率/风险/日期/下一步）。
- 工单状态与处理结果流转。
- 订单履约与取消（取消释放库存、恢复信用、回退已转数量）。
- 项目改名 SalesDeck；多厂商 Provider；Cloudflare Tunnel；文档与 GitHub 交付。

## 4. AI 生成代码如何验证

每一步都不只看「能跑」，而是分层验证：

| 层级 | 手段 | 当前结果 |
|---|---|---|
| 类型 | `pnpm typecheck` | shared / server / web 全部通过 |
| 单元/集成 | `pnpm test` | shared 14 + server 146 |
| 浏览器端到端 | `pnpm test:e2e` | 19 条 Playwright |
| Agent 行为 | `pnpm eval` | 30/30 golden cases |
| 生产构建 | `pnpm build` + `node apps/server/dist/index.js` | 通过 |
| 人工验收 | 截图 / 实际点击 | 用户逐项验收并提出修复 |

关键测试覆盖：

- 定价阶梯、价格底线、信用超额、库存拆仓、乐观锁。
- 确认令牌：签名、用户绑定、载荷哈希、过期、一次性。
- 幂等：重复提交返回首次结果，复用键返回冲突。
- 14 个工具契约与角色权限。
- 优先级引擎、workspace 聚合、客户/联系人/商机/工单/订单编辑。
- 拆单转单、部分转单审批、取消订单回滚。
- SSE、会话连续性、RAG 证据门槛、OpenAI 网关。

## 5. AI 出错与纠正记录

这部分是课程要求的「对 AI 生成代码的校验与兜底」证据。

| 问题 | 根因 | 修正 |
|---|---|---|
| 种子排序测试随日期漂移 | 月度订单时间跨月 | 固定 `now`，按本地月初 clamp，并加 `lib/time.ts` |
| shared 枚举与 Drizzle 枚举漂移 | 两处各写一份 | shared 单一来源 + 类型约束 + 漂移测试 |
| 主动写工具测试偶发失败 | `Date.now()` 在预览和提交各算一次，令牌载荷不一致 | 一次计算、两处复用 |
| 拆单转单没有生效 | better-sqlite3 `.transaction(fn)` 返回函数，未调用 | 补 `()()` 并加订单履约/取消测试 |
| E2E 端口 5174 残留 | 上一次 Vite 未退出 | 按 PID 清理；Playwright 串行 `workers: 1` |
| 角色切换后页面回到销售 | `page.goto` 会重置未持久化的 Zustand 状态 | E2E 改为通过应用内导航切换 |
| 审批驳回后报价仍叫「已批准」 | 转单驳回 ≠ 报价驳回 | 列表/详情同时展示「已批准 + 转单被驳回」，并解释语义 |
| 工具调用次数超限 | 图预算过紧 | 单工具 2→3、总步数 8→10，并给可执行提示 |

## 6. 人工决策点

以下不是 AI 自行决定的：

- 产品定位：从「销售问 AI」升级为「作战室」。
- 安全底线：预览 → 确认 → 执行；权限、价格底线、审批不可绕过。
- 角色权限：销售不得直接调额、不得取消订单；经理可审批与直接操作。
- 范围裁剪：不做真实支付/物流/ERP，不做多租户 SaaS。
- 命名：SalesDeck。
- 部署方式：Cloudflare Tunnel 公网演示。

## 8. 结论

AI 在本项目中承担了**设计草案、代码实现、测试编写、故障定位、文档整理**的大部分执行工作；人工负责**产品方向、安全边界、权限规则、验收与取舍**。所有关键业务规则都有测试或 E2E 兜底，AI 的产出通过构建、测试、评测与人工点击四层验证后才进入提交。
