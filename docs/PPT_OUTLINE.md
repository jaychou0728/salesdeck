# SalesPilot 答辩 PPT 提纲（10 页）

> 建议时长 8–10 分钟，5 分钟演示视频/现场穿插在第 3 页。
> 叙事主线：销售的一天如何被 AI 接管 → 为什么它敢做写操作 → 工程证据。

---

## Slide 1｜封面

- 标题：**SalesPilot 销售作战室**
- 副标题：能替销售跑完一单、每一步都敢给经理看的 AI 销售同事
- 场景：腾讯 AI Coding 课程作业 · 方向二 · 场景 3
- 技术栈一行：React · Fastify · LangGraph.js · SQLite/Drizzle · DeepSeek / Mock
- 底部：姓名 / 日期 / 仓库地址

**讲述**：一句话定位，不铺垫。

---

## Slide 2｜痛点：销售的一天被切碎了

- 客户资料在 CRM、库存在表格/ERP、价格政策在文档、审批在群里
- 一单要走：查客户 → 问库存 → 算阶梯价 → 核信用 → 做报价 → 等审批 → 转订单 → 售后
- 现状：AI 客服只会“聊天”，不敢落库；传统 CRM 只会“记录”，不会办事
- 关键问题：**AI 能不能在受控前提下，真正完成写操作？**

**讲述**：用 3 个具体动作说明碎片化，落到“写操作才是分水岭”。

---

## Slide 3｜产品演示（5 分钟视频 / 现场）

动线截图或录屏：

1. 晨报：华辰信用仅剩 8%、X1 低于安全库存、2 张报价 48h 到期
2. 一句话报价：「给华辰设计的张总报 120 台 X1」→ 搜客户 → 查三仓 → 阶梯价 → 报价预览
3. 风控：信用不足 → 转订单进入经理审批 → 批准后建单、锁库存
4. 售后：「开不了机怎么处理」→ 检索 DOA 政策带引用 → 工单预览 → 落库
5. 回放：右侧执行链路展开工具、参数、结果、耗时

**讲述**：让画面说话，只补充“注意它停在预览/审批，没有直接写”。

---

## Slide 4｜系统架构

- 一张图：React 两栏 → Fastify → LangGraph → Tool Registry → Domain / RAG → SQLite
- 双链路：业务工具链路 + 政策知识链路，共用 Provider 与 SSE
- Provider 适配：DeepSeek（OpenAI 兼容）/ Mock（确定性降级）
- 关键边界：权限在工具层、写操作在确认层、审批在持久化层

**讲述**：强调“分层不是画着好看”，每层对应一个安全边界。

---

## Slide 5｜工具契约与风控（核心页）

- 9 个工具：6 读 + 3 写（客户、360、库存、定价、知识、晨报 / 报价、转订单、售后）
- 统一信封：`ok/data/meta` 或 `error/code/recoverable/suggestedAction`
- 三层防线：
  1. 输入：Zod 强校验 + 角色/数据范围
  2. 执行：服务端定价、库存乐观锁、事务、状态机
  3. 提交：dry-run + 一次性令牌 + 幂等键 + 审批
- 模型输出不可信：未知工具、非法 JSON、越权请求一律结构化拒绝

**讲述**：这是答辩技术深度的主页，逐条对应代码。

---

## Slide 6｜RAG：不编造的政策问答

- 6 篇知识文档 → 标题切块 → 本地 1024 维 n-gram 哈希向量
- 混合检索：BM25 + 向量 + RRF 融合
- 证据门槛：ASCII 词 ≥2 或中文 bigram 命中才算证据；单字不算
- 不足时明确说“资料中没有”，建议转人工/建工单
- 引用粒度：docTitle + section + snippet + chunkId

**讲述**：重点讲“证据门槛”，解释为什么不会拿“设计”的“计”去回答无关问题。

---

## Slide 7｜评测与测试数据（用数字说话）

- Agent 评测：25 条 golden cases，覆盖意图、工具选择、越权、边界、幂等、售后、政策引用
- 当前通过率：**100%（25/25）**，报告由 `pnpm eval` 生成
- 服务端测试：73 个 Vitest（定价、库存、信用、状态机、幂等、令牌、网关、SSE、路由、RAG）
- E2E：2 条 Playwright（晨报 → 报价 → 审批 → 下单 → 售后）
- 说明：评测使用确定性 Mock，验证的是编排与契约正确性；真实模型能力需另行评估

**讲述**：诚实区分“工程正确性”与“模型泛化”，主动说明 Mock 的边界。

---

## Slide 8｜交付与运行

- 本地 5 分钟：`cp .env.example .env` → install → migrate → seed → `pnpm dev`
- 一键脚本：`scripts/smoke.sh`（health + OpenAI 网关 + SSE）
- Docker：多阶段构建 + compose + healthcheck + 数据卷（**本机无 Docker，尚未实机验证**）
- 文档：README、ARCHITECTURE、ADR、DEMO_SCRIPT、EVAL_REPORT、PPT 提纲
- 离线兜底：Mock 模式 + 演示数据一键 reset

**讲述**：主动披露 Docker 未验证，比假装验证更加分。

---

## Slide 9｜关键取舍（ADR 摘要）

- SQLite + Drizzle：零运维换并发上限
- LangGraph 显式图：可控/可解释换部分自主规划
- Mock 降级：可复现换真实模型覆盖
- 确认令牌 + 幂等：安全换一步操作
- 持久化审批：可恢复换单会话顺滑
- 本地 n-gram：离线换语义深度
- 单位：一句话——**“先保证敢写，再追求写得聪明”**

**讲述**：每项都说清代价，展示工程判断而非堆技术。

---

## Slide 10｜复盘与下一步

- 做得好：端到端闭环、写操作安全、可解释事件流、评测先行
- 不足：
  - 意图/槽位依赖规则，复杂多轮澄清弱
  - 本地 embedding 语义能力有限
  - Docker 未实机验证
  - 演示身份切换非真实认证
- 下一步：真实 embedding / 重排、图检查点与多轮记忆、审批通知、Docker CI、真实模型回归评测
- 收尾一句：**SalesPilot 证明 AI 可以在受控边界内，真正替销售办事。**

**讲述**：用“已知限制 + 下一步”收尾，留出提问空间。

---

## 附：可能被问到的三个问题

1. **模型乱调工具怎么办？** 工具白名单、Zod 校验、单工具 2 次/总 8 步预算、结构化错误回传、降级回复。
2. **令牌会不会被模型拿到？** 令牌只通过 SSE artifact 下发前端，写工具返回给模型的结果已剥离；令牌绑定用户+载荷+有效期且一次性。
3. **100% 评测是不是刷出来的？** 评测固定 Mock、固定 25 条用例，验证的是编排与契约；真实模型能力不在此数字内，报告与脚本均公开可复跑。
