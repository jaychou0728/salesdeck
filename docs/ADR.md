# 架构决策记录（ADR）

记录本项目 8 个关键取舍。格式：背景 → 决策 → 代价与取舍。实现现状见 [`ARCHITECTURE.md`](ARCHITECTURE.md)。

---

## ADR-001：TypeScript + pnpm workspace 单仓

**背景**：前后端共享工具契约、错误码与类型；7 天单人交付，需要最少的心智负担与一键构建。

**决策**：pnpm workspace 管理 `apps/server`、`apps/web`、`packages/shared`。`shared` 只放 Zod schema、类型、错误码；构建顺序固定为 shared → server/web。

**取舍**：
- 优点：契约单一来源，改 schema 前后端同时报错；`pnpm build/test` 统一入口。
- 代价：workspace 链接与构建顺序需要显式维护（根脚本已固定）；不使用 Turborepo 等缓存工具，规模变大后构建会变慢。

## ADR-002：SQLite + Drizzle，金额以“分”存整数

**背景**：演示环境要求零运维、可离线、数据可重置；金额精度与迁移可复现是硬要求。

**决策**：使用 better-sqlite3 + Drizzle ORM，迁移文件入库；所有金额字段以整数分存储；seed 固定 ID 且有效期相对当前时间生成。

**取舍**：
- 优点：单文件数据库、Docker 友好、迁移可重放；整数分避免浮点误差；同步驱动让事务与工具执行简单可靠。
- 代价：并发写入能力有限，不适合多实例生产；数据访问层虽隔离，但换 Postgres 仍需改部分 SQLite 方言（如 WAL、同步事务）。

## ADR-003：LangGraph 显式状态图 + 硬预算

**背景**：Agent 需要可解释、可控地循环调用工具；答辩需要讲清“为什么不会无限调用/越权”。

**决策**：用 LangGraph.js 定义 `classify → retrieve/agent ⇄ tools → respond` 的显式状态图；单工具最多 2 次、整体步数上限 8、超限进入降级回复；模型输出视为不可信输入。

**取舍**：
- 优点：流程可视化、条件边清晰、预算可强制；未知工具/非法 JSON/越权在工具层拦截。
- 代价：意图与槽位主要由规则启发式完成，复杂多轮澄清能力弱于纯 LLM 规划；图的状态字段需要随功能扩展同步维护。

## ADR-004：Provider 适配层 + 确定性 Mock 降级

**背景**：现场网络/API Key 不可控；协议测试与 Agent 评测需要稳定、可重复的输出。

**决策**：定义 `ChatProvider` 接口，提供 `DeepSeekProvider`（OpenAI 兼容）与 `MockProvider`。`LLM_PROVIDER=mock` 或缺少 Key 时自动使用 Mock；Mock 按关键词返回固定的工具调用脚本。

**取舍**：
- 优点：离线可完整演示；评测不依赖外部模型，结果可复现；同一套运行时同时服务真实模型与 Mock。
- 代价：Mock 只覆盖预置场景，不能证明真实模型的泛化能力；真实模型的稳定性需另行验证，评测数字应理解为“契约与编排正确性”，而非模型能力上限。

## ADR-005：统一工具注册表（Zod + 权限 + 审计 + 事件）

**背景**：9 个工具若各自处理校验、权限、日志，会出现安全与可观测性缺口。

**决策**：每个工具声明 `name/description/inputSchema/kind/allowedRoles/execute`；`executeTool` 统一完成 `step.start` → Zod 校验 → 角色校验 → 执行 → 审计落库 → `step.end` → artifact 事件；返回值统一 `ToolResult` 信封与错误码。

**取舍**：
- 优点：越权、参数错误、异常都有一致的结构化响应；前端与评测都能只依赖事件；审计天然完整。
- 代价：工具实现受统一签名约束；对特殊流式/长任务工具（当前没有）扩展性一般。

## ADR-006：写操作 dry-run + 一次性确认令牌 + 幂等键

**背景**：模型不能直接落库；重复点击/重试不能重复建单或重复扣库存。

**决策**：所有写工具先 `dryRun=true` 返回预览；服务端签发 HMAC 令牌（绑定用户、工具、载荷哈希、10 分钟有效期），只通过 SSE artifact 下发前端，模型侧不持有；提交必须同时携带令牌与幂等键。令牌一次性消费；幂等键按稳定序列化哈希去重，重复请求返回首次结果。

**取舍**：
- 优点：模型无法自我确认；前端确认路径清晰；重试安全。
- 代价：前端需要维护预览→确认的交互状态；令牌过期需重新预览；多一步用户操作换取安全性。

## ADR-007：审批采用持久化状态，而非图中断

**背景**：信用超额、报价低于底线需要经理审批；演示中会切换角色，服务也可能重启。

**决策**：审批落 `approvals` 表，记录类型、目标、申请人、状态与意见；图在预览阶段结束，经理通过独立幂等接口 `POST /api/approvals/:id/decide` 决策，批准后再创建订单/放行报价。不依赖 LangGraph checkpoint 或长生命周期 interrupt。

**取舍**：
- 优点：角色切换、重启都不丢审批；审批与业务事务解耦，接口可独立测试；权责清晰。
- 代价：前端需要在“待审批”与“已批准”之间轮询/刷新；没有图 interrupt 那种单会话内自动续跑的顺滑体验。

## ADR-008：本地 n-gram 向量 + BM25/向量 RRF + 证据门槛

**背景**：演示不能依赖外部 embedding 服务；中文 FTS5 分词不可靠；政策问答必须避免编造。

**决策**：知识库按标题切块；使用字符 n-gram 哈希向量（1024 维）做语义近似，BM25 做关键词召回，RRF 融合取 Top K；只有与查询共享真实词项（ASCII 词 ≥2 字符或中文 bigram，含少量口语别名）的 chunk 才计为证据，否则明确回答“资料中没有”。

**取舍**：
- 优点：零外部依赖、离线可跑；证据门槛显著降低越界回答；引用可追溯到 chunk。
- 代价：哈希向量语义能力弱于神经 embedding，同义改写召回有限；词法门槛可能漏掉合理但措辞差异大的问题，需靠别名表与文档措辞缓解。
